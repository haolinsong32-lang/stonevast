用途：让「实际到账」从 `unconfigured` 变为可核验的真实数据。本文档只说明需要你提供什么，不代替你做任何链上写操作。

## 一、当前不能直接开启采集的原因（技术事实）

配置公开地址只是第一步，还缺两件事：

1. **四条链的公开地址、网络、披露方式**都还没有收到具体值。系统不会猜测或编造地址。
2. **采集适配器尚未实现。** [payout_adapters.py](file:///D:/AI/石广/石广项目/官网/payout-server/payout_adapters.py) 中的 `build_default_adapters()` 目前返回空字典。即使填了地址，服务也只会记录 `adapter_unsupported`，页面继续显示不可用。

所以正确顺序是：

```
你提供公开地址 + IRON 脱敏导出
→ 我核验每条链的只读公开数据源
→ 实现 KAS / PRL / QUAN（full）+ IRON（limited）四个适配器
→ 本地与生产 Python 3.6 测试
→ 写入 systemd 环境变量、重启、验证接口
→ 页面自动显示真实到账
```

在适配器完成前，我不会把地址写进生产配置，避免出现「看起来已开启、实际是错误状态」的假象。

## 二、四链需要你提供的信息

逐条填写，缺任意一项该链保持 `unconfigured`。

| 链 | 需要填写 | 说明 |
| --- | --- | --- |
| KAS | 公开收款地址 / 网络名（如 mainnet）/ 披露方式 | 披露方式 `masked`（页面只显示前 6 后 4 位）或 `full`（完整显示） |

- 如果某条链暂时不想公开，直接说明「该链暂不配置」，保持现状即可。

## 三、IRON 脱敏导出模板字段

文件：[IRON钱包交易导出脱敏模板.csv](file:///D:/AI/石广/石广项目/官网/payout-server/导入模板/IRON钱包交易导出脱敏模板.csv)

文件带 UTF-8 BOM，方便 Excel / WPS 直接双击打开不乱码。模板里的两行是**示例，导入前请整行删除**。

| 列名 | 是否必填 | 约束 |
| --- | --- | --- |
| 序号 | 是 | 从 1 递增，仅用于人工核对 |
| 链 | 是 | 固定 `IRON` |
| 资产 | 是 | 固定 `IRON` |
| 交易哈希 | 是 | 交易 ID，不含私钥、签名或助记词 |
| 输出序号 | 二选一 | UTXO 类链填此项；与「日志序号」至少填一个 |
| 日志序号 | 二选一 | EVM 兼容链填此项；与「输出序号」至少填一个 |
| 金额原子数 | 是 | **只能是整数**，禁止小数和科学计数法；按精度换算后的最小单位 |
| 精度 | 是 | 该资产的小数位数，以钱包导出为准 |
| 区块高度 | 是 | 整数 |
| 区块时间UTC | 是 | ISO8601，如 `2026-11-17T02:30:00Z`；导入时统一转 Unix 秒 |
| 确认数 | 是 | 整数，0 表示尚未确认 |
| 最终性 | 是 | 如 `final`、`confirmed`，按链的实际表述填写 |
| 事件状态 | 是 | 只能是 `pending` / `finality` / `reorg` / `reverted` |
| 分类 | 是 | 只能是 `pool` / `other` / `pro` / `self` / `unknown`；只有 `pool` 计入合计 |
| 验证级别 | 是 | IRON 固定 `limited` |
| 来源 | 是 | 如 `wallet-export`，用于区分证据来源 |
| 浏览器链接 | 是 | 公开可访问的交易页地址，用于页面上「查看链上记录」 |
| 内部转账 | 是 | `true` / `false`；自转不计入合计 |
| 找零 | 是 | `true` / `false`；找零不计入合计 |
| 备注 | 否 | 仅内部参考，不对外展示 |

### 关键约束

- 同一 `交易哈希 + 输出序号/日志序号` 只允许出现一次，否则会被判为同一笔事件。
- `reorg` / `reverted` 会保留审计记录，但退出合计。
- IRON 走 `limited` 验证，页面只显示「资产、交易哈希、状态、浏览器链接」，不会把金额与其他三链合并，也不会进入完全核验合计。

## 四、绝对不能提供的内容

以下任何一项都不要写进 CSV、不要粘贴到聊天、不要上传：

- 私钥、助记词、Keystore 文件及其密码
- 钱包密码、交易所登录凭据、2FA 验证码
- 带 `token=` / `apikey=` 的私人接口地址
- 未脱敏的完整资金流水截图（含余额以外的个人信息）

如果某个链接必须带凭据才能打开，说明它是私有接口 —— 这种链接不能作为公开证据，请换用公开区块浏览器地址。

## 五、TG / QQ 实际能做什么（授权后的技术边界）

工具层有两条硬限制，必须说清：

1. **TG bot 无法主动私聊陌生人。** Telegram 不允许 bot 主动私聊未与它对话过的用户，所以「去多个群私聊成员」在技术上做不到，换任何脚本都一样。
2. **没有 QQ 消息工具。** 本机现有能力里只有 QQ 邮箱（IMAP/SMTP 收发邮件），没有 QQ 群或 QQ 私聊的发送接口。用邮件给 QQ 群发消息也不成立。

当前执行方式：

- **TG 由你自行通过 bot 发布**：我只准备和更新文案，不代发、不重复置顶。历史完整版 `msg_id=24` 和精简版 `msg_id=26` 已发送，不得当作新公告再次发布。
- **可复制文本**：见 [无限代理权益与结算规则-20261117.md](file:///D:/AI/石广/石广项目/推广/无限代理权益与结算规则-20261117.md)，用于你自愿进行的一对一沟通或公开发布。

不批量私聊陌生人：平台可能判定为骚扰，也会损害 StoneVast 的可信度。

代理权益与结算口径已与站内页面一致：邀请关系与分成资格均不限层级；L1 默认 5%（创世直推 30%）、L2 2%、L3 1%、L4 0.5%、L5 0.25%，后续逐级减半。当前核心只按符合条件的真实净产出计算整数权益，最小单位取整后可能为 0；权益不等于实际付款，可信的「链上事件 → 产币节点 UID」映射建立前，生产结算不开启。
