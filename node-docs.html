一、目的与合规底线

  1. 本文说明三类参与路径（邀请码、创世凭证、Pro 工具）的发放与使用流程。
  2. 邀请树不设深度上限；返佣最多三级：L1 使用邀请人的配置费率，L2 为 2%，L3 为 1%；第四级及以下只保留关系、不参与分成。
  3. 官方自有算力为 0 级，不参与任何层级分成。
  4. 所有收益数字均为预估 / 结构演示，不构成收益承诺；真实结算后续开启。

三、凭证格式与含义

  1. 卡密 / 凭证（key）：SV-XXXXXXXX，由官方生成，用于注册或激活。类型 C = 普通注册凭证；B = 创世凭证。Pro 订阅不使用节点卡密。
  2. 邀请码（invite_code）：N-XXXXXXXX，每个用户注册后自动获得一枚，可继续邀请新节点，关系树不设深度上限。
  3. 字符集去掉易混淆的 0 / O / 1 / I，人工抄写不出错。

四、官方发放流程

谁发放：仅 StoneVast 官方（运营方）有权生成卡密 / 凭证，生成动作写入卡密表，初始状态 unused。
发放渠道：
　① 免费邀请码（C）：官网公开领取 / 社群发放 / 早期用户活动；
　② 创世凭证（B）：限量发行，仅通过官方渠道（活动、早期贡献者、定向名额）发放，控制总量；
　③ Pro 工具：支付 API 迁移期间暂停收款和 TXID 自助激活；已有订阅用户可沿用当前密码，其他用户请等待恢复公告，恢复前请勿付款。
状态流转：unused（未使用）→ 注册 / 激活后 → used（已使用），记录使用者与使用时间。一枚凭证只能用一次，用过即作废。

五、注册与激活流程

新用户注册（标准节点） POST /register，参数 {key, invite_code}：校验卡密有效且未使用 → 如填邀请码则绑定父节点 → 生成 uid 与自己的邀请码 → 按卡密类型定身份（C → user 默认 L1 5%；B → genesis L1 最高 30%）。
已有用户升级 POST /activate，参数 {key, uid}：仅 B 凭证升级为创世节点，L1 最高 30%；Pro 订阅与节点激活互不绑定。
邀请码查询 GET /node/lookup?code=N-XXXX，返回邀请人 uid 与分成比例。

六、三级返佣规则

  1. 分成基数：真实工具付费或实际净产出（产出 − 电费等直接成本），不按注册人数、所持凭证或入门费计酬。
  2. 分成比例：标准节点 L1 默认 5%，创世节点 L1 最高 30%；L2 统一 2%，L3 统一 1%。Pro 不改变这些比例。
  3. 层级边界：邀请关系可无限延伸，但第四级及以下不参与返佣；查询接口最多遍历 10 层，返佣仍只认前三级。
示例：A 邀请 B、B 邀请 C、C 邀请 D、D 再邀请 E。D 的真实合格产出可按规则分别计入 C 的 L1、B 的 L2、A 的 L3；E 与 A 仍保留邀请关系，但 A 不从 E 获得返佣。所有结算都以真实记录为准，不是收益承诺。

七、关系与账本接口

GET /node/my?uid=sv_xxx 返回我的节点、钱包记录和前三层人数；GET /node/downline?uid=sv_xxx&depth=3 返回下线树（最多查询 10 层）；GET /node/lineage?uid=sv_xxx 返回上级链、实际费率和是否参与返佣。
这些接口只返回关系与估算结构，不代表已产生应付款，也不自动结算。首页计算器中的 L1/L2/L3 均为估算，真实结算必须另有可核验记录。

八、结算状态

  1. 当前阶段：钱包绑定仅做记录，不收款、不自动结算。
  2. 真实结算（IRON 链上转账、自动分账）尚未开启。开启前必须增加节点身份密钥、操作审计和异常改绑保护，再按真实记录生成结算单并由用户确认；仅凭 UID 不得自动打款。

九、常见问题

Q：邀请树无限深，是否每一级都有返佣？
不是。只有 L1/L2/L3 参与返佣，第四级及以下仅保留关系；查询最多遍历 10 层。

Q：创世凭证、邀请码和 Pro 有什么区别？
邀请码免费、标准 L1 默认 5%；创世凭证限量、L1 最高 30%；两者 L2 均为 2%、L3 均为 1%。Pro 是独立工具订阅，不提高返佣。

Q：分成是承诺收益吗？
不是。所有数字均为结构演示，不构成收益承诺。
