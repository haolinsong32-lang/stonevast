一、目的与合规底线

  1. 本文说明三类凭证（邀请码、创世凭证、Pro 权益）的官方发放与使用流程。
  2. 分成仅限一级直推：你邀请的人挖矿，你按其净产出拿分成；对方再邀请的人与你无关。禁止二级及以上返佣，从制度上规避传销风险。
  3. 官方自有算力为 0 级，不参与任何层级分成。
  4. 所有收益数字均为预估 / 结构演示，不构成收益承诺；真实结算后续开启。

三、凭证格式与含义

  1. 卡密 / 凭证（key）：SV-XXXXXXXX，由官方生成，用于注册或激活。类型 C = 普通注册凭证；B = 创世凭证；P = Pro 权益凭证。
  2. 邀请码（invite_code）：N-XXXXXXXX，每个用户注册后自动获得一枚，用于邀请下一级（一级直推）。
  3. 字符集去掉易混淆的 0 / O / 1 / I，人工抄写不出错。

四、官方发放流程

谁发放：仅 StoneVast 官方（运营方）有权生成卡密 / 凭证，生成动作写入卡密表，初始状态 unused。
发放渠道：
　① 免费邀请码（C）：官网公开领取 / 社群发放 / 早期用户活动；
　② 创世凭证（B）：限量发行，仅通过官方渠道（活动、早期贡献者、定向名额）发放，控制总量；
　③ Pro 权益（P）：付费购买，收款由用户本人完成（敏感财务信息不由助手代填）。
状态流转：unused（未使用）→ 注册 / 激活后 → used（已使用），记录使用者与使用时间。一枚凭证只能用一次，用过即作废。

五、注册与激活流程

新用户注册（标准节点） POST /register，参数 {key, invite_code}：校验卡密有效且未使用 → 如填邀请码则绑定一级直推关系 → 生成 uid 与自己的邀请码 → 按卡密类型定身份（C → user 5%；B → genesis 30%）。
已有用户升级 POST /activate，参数 {key, uid}：B 凭证升级为创世节点 30%；P 凭证升级为 Pro 节点，分成 0~100% 自调。
邀请码查询 GET /node/lookup?code=N-XXXX，返回邀请人 uid 与分成比例。

六、一级分成规则

  1. 分成基数：直推节点的净产出（挖矿产出 − 电费），不是毛产出。
  2. 分成比例：标准节点默认 5%，可调上限 20%；Pro 节点 0~100% 自调；创世节点固定 30% 永久。超出身份上限的设定会被系统拦截。
  3. 分成方向：只从直推节点 → 邀请人，单向、一级，不向上传播。
链条问题（常见疑问）：A 邀请 B，A 拿 B 的分成；B 再邀请 C，只有 B 拿 C 的分成，A 拿不到 C 的一分钱。这条链不会一直推回去——系统只认「直接邀请」这一层，这正是防传销的合规设计。

七、分成账本结构

调用 GET /node/ledger?uid=sv_xxx 返回：我的信息（uid、邀请码、分成比例、身份、是否已绑钱包）+ 直推列表（每个直推节点的 uid、注册时间、身份、是否已绑钱包）。
账本只回传结构，不结算、不暴露钱包明文地址。官网首页的「节点分成估算器」已与此账本结合：输入直推节点数、每节点算力、你的分成比例，即可估算每日 / 每月分成（仅结构演示）。

八、结算状态

  1. 当前阶段：钱包绑定仅做记录，不收款、不自动结算。
  2. 真实结算（IRON 链上转账、自动分账）后续开启，届时将：收紧钱包地址校验（精确长度 + 链上交叉核验）→ 按账本结构生成结算单 → 用户确认后打款。

不能。只做一级直推分成，制度上禁止二级及以上返佣。

邀请码免费、默认 5%（上限 20%）；创世凭证限量、30% 永久高分成；Pro 付费、0~100% 自调。

Q：分成是承诺收益吗？
不是。所有数字均为结构演示，不构成收益承诺。
